# Neo

**面向特定目标的灵活 Agent 系统。**

> English: [`README.md`](README.md)

给它一个要完成的目标（查状态、整理材料、跑一套固定办事流程……），Neo 会按约定把任务做完。它不追求「什么都能聊」，而追求**把某一类事办扎实**。

做事靠两根支柱：

| 支柱 | 业务上怎么理解 | 它管什么 |
|------|----------------|----------|
| **DAG（流程蓝图）** | 任务怎么一步步往下走、数据/结果如何交接 | **调度**：先做什么、后做什么、哪步依赖哪步 |
| **能力矩阵** | 允许用的「本事」清单（读文件、白名单命令、外部接口等） | **调用**：这一步具体使哪项能力 |

再加上权限与边界（哪些事默认不许做），形成完整的办事纪律：大模型负责理解和生成，Neo 负责**按图调度、按清单使能力**。

拷到不同机器上改配置就能用，像随身**瑞士军刀**，而不是一整套重型工作室。

场景与定位的完整表述见 [`docs/applications.md`](docs/applications.md)；上手命令见下文与 [`docs/examples.md`](docs/examples.md)。

## 业务上能铺到哪里

Neo 的价值不在「模型谁更强」，而在**目标型 Agent 能否稳定调度、按清单使能力、并控住成本与边界**。下面与 [`docs/applications.md`](docs/applications.md) 同一套层次：先写今天能落地的，再写方向与愿景（后两层勿当作已全部交付）。

### 能落地：让 Agent 任务真正办完

面向个人、小团队与业务运营里最常见的「落地难」：

| 业务诉求 | Neo 怎么撑住 |
|----------|----------------|
| **多步骤目标要跑完、可复查** | 用 DAG 把「取数 → 整理 → 判断 → 通知/落盘」写成可重复的调度图；同一目标多次执行路径清晰 |
| **企业内部本事很多，要给 Agent 用且可控** | 用能力矩阵登记脚本、命令、接口等原子能力；任务只能调用清单内能力，而不是任意放开 |
| **别事事回云端：贵、慢、数据也不想乱传** | 简单步骤优先走本地能力，难推理再调大模型；在授权范围内把敏感操作留在信任边界内 |

典型画面：仓库/文档旁路助手、定时交代一个目标就执行、按 SOP 跑日常检查——**当前仓库交付的重点就在这一层**。

### 往前走：现场与边缘（方向）

当「近数据、低时延、弱网仍要闭环」成为硬需求时，同一套「DAG 调度 + 能力矩阵」可向现场延伸（完整形态见架构路线图，今日以预留与契约为主）：

| 方向 | 业务画面 | Neo 扮演的角色 |
|------|----------|----------------|
| **工业边缘** | 质检、联锁、异常处置要在产线侧闭环 | 工控侧调度流程，节点侧执行已登记能力；网络不稳时仍尽量走完关键路径 |
| **具身与移动平台** | 巡检、服务机器人、机载任务编排 | 任务级调度与能力治理（不替代底层硬实时运动控制） |
| **楼宇 / 厂区联动** | 传感触发后的跨设备动作要快、路径要短 | 区域侧按图调度，授权内减少「事事绕公有云」 |

### 更远：智能基础设施（愿景）

架构成熟后，业务形态可能从「一个助手」长成「一层基础设施」（**非现行功能清单**）：

- 设备上以「能力包」扩展，而不是只堆传统 App  
- 家庭或组织网关里的**私有数字助理**：邮件、文档、浏览器等能力按图调度，敏感数据默认不出信任域  
- 跨系统的能力分发与复用，形成可治理的能力生态  

### 生态位（一句话）

云端大模型提供深度认知；**Neo 提供把智能接进真实系统的调度与执行脊梁**——不替代大脑，而是让目标可编排、能力可治理、边界可守住。细则与成熟度对照见 [`docs/applications.md`](docs/applications.md) 第 5–6 节。

## 谁会用得上

- 需要围绕**明确目标**跑 Agent 任务的个人或小团队  
- 希望同一类目标**走法可控、结果可复查**的业务 / 运维  
- 希望部署轻便：换环境改配置即可，不必先上沉重平台  

若你要的是「最强写代码 IDE」或「超大工作流中台」，Neo 不是那个方向——我们刻意做灵活、可落地、边界清晰。

## 现在就能用来干什么

与上文「能落地」对应，本机已经可以：

1. **交代一个目标就办**：自然语言下达，规划步骤后执行（也可只看计划）。  
2. **按已定 DAG 办**：常用目标写成流程，一键按图调度。  
3. **按能力矩阵使能力**：在授权范围内读文件、搜仓库、调用已登记命令。  
4. **嵌进日常节奏**：终端、常驻听吩咐、定时 / 管道——同一套 Agent，多种唤起方式。

## 五分钟开始用

1. 准备一台能上网的 Mac 或 Linux（用来调用你选的大模型服务）。  
2. 在本仓库目录执行：`make`（生成程序 `neo`）。  
3. 复制配置，填入模型地址和密钥：

```bash
cp config/config.json5.example config/config.json5
# 打开文件，填入 api_key 和模型名称
```

4. 试一下：

```bash
./neo "你是谁"
```

## 试几句就懂

在仓库根目录执行（先配好密钥）：

```bash
# 了解它能帮业务完成什么样的目标
./neo "用三句话说明 Neo 适合完成哪些目标型任务"

# 按现成 DAG 跑一个小目标：查看当前时间
./neo dag run show_time

# 旗舰工作区 SOP：列目录 → 简报 → 追加 WORKSPACE_BRIEF.md
./neo dag run workspace_brief

# 用一句话交代目标：规划并执行
./neo run "看下系统时间"

# 让 Agent 使用「读文件」能力，再概括产品价值
./neo "请阅读 README.md，用三句中文概括产品价值。"

# 只要计划（DAG 草案），先不动手
./neo plan "帮我摸清当前仓库最近在忙什么"
```

更多例子见 [`docs/examples.md`](docs/examples.md)。

## 平时怎么用（记住三种就够）

| 你想… | 怎么说 |
|-------|--------|
| 随便问一句 | `./neo "你的问题"` |
| 按已定 DAG 完成目标 | `./neo dag run 流程名`（或 `./neo run 流程名`） |
| 用一句话交代目标并自动办完 | `./neo run "要完成的目标"` |

只要计划、先不执行：把 `run` 换成 `plan`。
